# 01. 点検実施画面

> ステータス：**確認済み（2026-10-21 レビュー反映）**
> 位置づけ：**本番で想定される機能の仕様**を記載する。画面デモは要件確認用のモックであり、デモ固有の挙動は仕様ではない（§10 に明記）。
> 表示パターンの一覧は [点検実施画面_表示パターン.md](./点検実施画面_表示パターン.md)（Marp）を参照。

## 1. 概要
- 目的：現場の作業者が、**その日の点検状況を確認し、点検を開始する**ための画面。
- 利用ロール：現場の作業者・取扱責任者・元請。ロールによる表示差は設けない（§5）。
- アクセス経路：**資機材ごとに発行したQRコードの読み取り**。読み取った時点で対象の資機材が1つに決まる。
- 対応デバイス：**スマートフォンとPCの両方**で利用する。基本はスマートフォンのため、本デモはスマホのモックイメージで作成している。スマホでは 390×844 を基準とし、**スクロールなしで全操作が1画面に収まる**ことを前提に設計する。

### 対象による2種類の画面

| 対象 | 点検の種類 |
|---|---|
| 機械（例：ELV-2） | 始業前点検（当日）／月例点検（当月） |
| 仮設・その他（例：わくぐみあしば） | 始業前点検（当日）／組立後等点検 |

- 画面のレイアウト（基本情報カード → 点検状態 → 操作ボタン）は両者で共通。
- 表示する点検の種類と操作ボタンの構成だけが異なる。

### 点検表の紐づけ
**点検表は資機材（QRコード）に紐づけて設定する。**「点検用QRコード印刷」で設定する。

| 紐づけ状況 | 表示 |
|---|---|
| 両方あり | 両方の帯（カード）を表示 |
| **片方のみ** | 紐づいている方だけ表示。**もう一方は帯ごと出さない** |
| **どちらも無し** | **帯を1つも出さない**。このときだけ案内を表示 |

- **どちらの点検表も紐づいていないとき**だけ、設定を促す案内を表示する。片方だけ紐づいている場合は出さない。
  > 「点検用QRコード印刷」で点検表を設定してください
- 紐づいていない点検の**開始ボタンは非活性**にする（点検表が無いと実施できないため）。
- 紐づいていない点検は**点検記録も存在しない**ため、点検元請確認の活性判定にも含めない。
- 機械の**当日ステータスは、始業前点検の点検表が紐づいていなければ「—」**（§3.1 ※1）。
- 点検表が未設定でも、**開始ボタン以外（記録確認・点検元請確認など）は制限しない**。

## 2. 画面要素
上から順に：
1. **ヘッダー**（水色の帯。`#35b7c4`）
2. **基本情報カード**（§3.1）
3. **点検状態の帯**（§3.2）
4. **操作ボタン**（§4）
5. **管理者メニュー**（区切り線付きラベル＋ボタン）

## 3. 表示項目

### 3.1 基本情報カード
| 項目 | 機械 | 仮設・その他 |
|---|---|---|
| 名称 | ○（大きく表示） | ○ |
| 使用期限切れバッジ | ○（赤バッジ） | — |
| 使用期間 | ○ | — |
| 当日の点検状況 | ○（例：7月17日 点検未／点検済）※1 | **×（持たない）**※2 |
| 取扱責任者（正）／（副） | ○ | ○ |

※1 **始業前点検の点検表が紐づいていない場合は「—」**を表示する。当日の点検という概念自体が無いため。
※2 **仮設・その他は基本情報カードに当日のステータスを持たない（日付も表示しない）。**
足場は1名が点検しても「済」が確定するとは言えず（複数人の点検が必要なケースがある）、
**システム側で点検完了の判定責務を持たない**方針のため。済んでいるかどうかの判断はユーザーに委ね、あえて明示しない。
実施状況は始業前点検・組立後等点検の帯／カードから読み取る。

- 使用期限切れの判定：**使用期間の終了日を過ぎたら**期限切れとする。赤バッジを表示するのみで、操作は制限しない（§8）。
- 取扱責任者が未登録のときは「—」を表示する。

### 3.2 点検状態の帯

#### 機械
**始業前点検（当日）** と **月例点検（当月）** の2つを、それぞれ帯で表示する。

| 状態 | 判定 | 表示 |
|---|---|---|
| 未 | 当日（当月）の点検記録が無い | 淡いピンクの帯／⚠️アイコン／ピンクの文字 |
| 済 | 当日（当月）の点検記録がある | 淡い青の帯／✓アイコン／青の文字 |

- 月例点検の帯には、**済・未のいずれでも最新点検日**を表示する（「今月実施済」「今月未実施」を併記）。

#### 仮設・その他
**「済」のステータスを持たない。** 点検が実施されていても「済」とは表示せず、**点検実施者の氏名を表示**する。

##### 点検の数え方（重要）
**1回の点検 ＝ 実施者1名 ＋ 実施事由1つ。実施者と事由は必ずセットで記録する。**

- 組立後等点検は、1回の点検で選べる**実施事由は1つだけ**。
- 1回の点検の**実施者も1名のみ**。
- ただし**QRコードを読み直せば何回でも点検できる**ため、実施するたびに「実施者＋事由」の組が1つずつ増える。
- 始業前点検も同様に、1回の実施につき実施者1名。繰り返し実施すると人数が増える。
- **実施回数に上限は設けない。** 同じ実施者が繰り返し点検した場合も、**実施した回数だけ記録を残す**。

##### 表示
| 区分 | 判定 | 表示 |
|---|---|---|
| 始業前点検 | 実施 0回 | **赤帯で「未」** |
| 始業前点検 | 実施 1回以上 | 中立のカードに**実施者名を連記**（「済」とはしない） |
| 組立後等点検 | 常に表示 | **`実施者（事由）` を1回1行**で並べる（0回なら空欄） |

**実施者と事由はセットで表示する。** 複数回実施した場合の例：

```
組立後等点検
田中 太郎（組立後等）
山本 健太（悪天候後）
```

- 始業前点検は事由を持たないため `実施者：佐藤 健、鈴木 一郎` と連記する。

- 「済」としない理由：**同じ足場でも使用者ごとに点検が必要**で、1名が点検しても完了とは確定しないため、人数で「済」とは判定しない。この扱いは**全現場共通**とし、現場ごとの設定は設けない。
- **点検完了の判定はシステムの責務外**とする。画面は「誰が・どの事由で点検したか」の事実のみを示し、完了とみなすかどうかの判断はユーザーに委ねる。
- 実施事由の選択肢は**固定**（マスタ化しない）：組立後等／悪天候後／地震後／定期／一部解体後／変更後／その他。

## 4. 機能・操作

### 4.1 ボタンの構成と階層
**主要アクションは1画面に1つだけ**塗りつぶして示す（始業前点検開始）。他は淡いグレー枠に落とす。

| 配置 | 機械 | 仮設・その他 |
|---|---|---|
| 全幅（主要） | 始業前点検開始 | 始業前点検開始 |
| 全幅 | 月例点検開始 | 組立後等点検開始 |
| 全幅 | 作業計画書・指示書確認 | 作業計画書・指示書確認 |
| 2列 | 記録確認 ／ 非稼働登録 | 記録確認 ／ 非稼働登録 |
| 2列 | 受理証確認 ／ 本日の予約 | — |
| 管理者メニュー（2列） | 点検元請確認 ／ 持込点検表一覧 ／ 過去点検記録確認 | 同左 |

- 管理者メニューは**全員に表示**する（一般の作業者にも見せてよい）。

### 4.2 活性・非活性
| ボタン | 非活性になる条件 |
|---|---|
| 始業前点検開始 | **始業前点検の点検表が紐づいていないとき** |
| 月例点検開始／組立後等点検開始 | **その点検表が紐づいていないとき** |
| 作業計画書・指示書確認 | **その機械（仮設）に作業計画書・指示書が紐づいていないとき** |
| 非稼働登録 | **当日の始業前点検が実施済みのとき**（機械＝「済」、仮設＝実施1回以上）。**機械・仮設とも同じ制御** |
| 点検元請確認 | **点検記録が1件も無いとき**（補足文「点検記録がありません」を表示） |

- 使用期限切れの資機材でも、**点検開始は止めない**。

### 4.3 操作感
- ボタンの高さは **48px以上**（手袋での操作を想定）。
- **ホバー効果は持たせない**（スマホにホバーが無いため）。
- 代わりに**下端の影で浮きを出し、押下時に沈ませる**（2px）。

## 5. ロール別表示差
- **この画面ではロール別の表示差は設けない**（デモ・本番とも同様。全ボタンを全員に表示）。
- 管理者メニューも全員に表示する。
- 点検元請確認は**元請ユーザー専用**の機能だが、アクセス可否は**遷移先のページ側で管理**する（この画面ではボタンを出し分けない）。

## 6. データ・外部連携
- 対象資機材は**QRコードから特定する**。QRは資機材ごとに発行する。
- 基本情報（名称・使用期間・取扱責任者）は持込機械／仮設の登録情報を参照する。
- 月例点検の最新点検日は点検記録から取得する。
- 本日の予約は予約機能（作業間調整Pro 側）を参照する想定。
- 各参照先の連携方式（同一DBか、別サービスのAPIか）は**エンジニアに一任**する。
- 「本日の予約」は**ボタン表示とする**（旧デザインのAM／PMカード表示は廃止。件数バッジは付けない。意図的な変更）。

## 7. バリデーション・制約
- 1画面に収めるため、**ボタンを追加する場合はレイアウトの再検討が必要**（現状ほぼ余白なし）。
- 実施者・実施事由は表示専用（この画面では編集しない）。

## 8. 例外・エッジケース
| ケース | 扱い |
|---|---|
| 使用期間外・使用期限切れの資機材を読み取った | 赤バッジを表示するのみ。**操作は制限しない**（点検開始も可） |
| 取扱責任者が未登録 | 「—」を表示 |
| 実施者が多数（5名以上）でカードが折り返す | 表示パターン⑥で確認済み |
| 点検表が未設定 | 開始ボタンのみ非活性。他のボタンは制限しない |
| 通信断（点検開始後の保存失敗） | 実装方法は**エンジニアに一任** |

| 使用期限切れの判定・点検開始の可否 | 終了日を過ぎたら期限切れ。点検開始は止めない |
| 取扱責任者未登録時の表示 | 「—」 |
| 実施事由の選択肢 | 固定（マスタ化しない） |

| 実施回数の上限・同一実施者の繰り返し | 上限なし。回数分の記録を残す |
| 非稼働登録の制御 | 当日の始業前点検が実施済みなら不可。機械・仮設とも同じ |

### 9.1 追加決定事項（レビュー反映 2026-10-27）
点検表の紐づけとステータス表示について、以下のとおり確定した。

| 論点 | 決定 |
|---|---|
| 機械の当日ステータスが指す範囲 | **始業前点検のみ**。月例点検の状態は反映しない。項目名は「当日の点検状況」のままとする |
| 月例点検のみ紐づいている場合（パターン⑥） | 当日ステータスは**「—」**（始業前点検の点検表が無いため。⑦と同じ扱い） |
| 仮設・その他の基本情報カードの情報量 | **名称＋取扱責任者（正）／（副）のみでよい**。使用期間などの追加は行わない |
| 仮設・その他の当日ステータス・日付 | **いずれも表示しない**。点検完了の判定はシステムの責務外とし、ユーザーの判断に委ねる（§3.2） |
| 点検表が未紐づけのときの資機材情報 | **使用期限切れバッジ・使用期間は従来どおり表示する**。点検に関する表示のみを落とす |

## 10. 本仕様と画面デモの差異
| モックの挙動 | 本番で想定する仕様 |
|---|---|
| 画面右（狭い画面では下）の「表示切替（デモ）」で状態を切り替える | **存在しない**。状態はデータから決まる |
| 実施事由を**複数まとめて選べる** | **1回の点検につき1つ**。繰り返し実施で増える |
| 実施人数を数値で増減できる | **1回の点検につき1名**。繰り返し実施で増える |
| 実施事由の選択がそのまま実施回数になる | QRを読み直して点検するたびに1組ずつ増える |
| ボタンはすべて表示のみで遷移しない | 各機能画面へ遷移する |
| 対象資機材は ELV-2／わくぐみあしば の固定サンプル | QRコードで特定した資機材 |
| 日付・点検状況はサンプル値 | 実データ |
| スマホのモックアップ枠の中に表示 | 実機のブラウザで全画面表示（PCでも利用可） |
