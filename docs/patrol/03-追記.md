# 03. 追記（巡回パトロール詳細画面内の機能）

> ステータス：ドラフト／要レビュー
> 本番で想定される仕様を記載する。デモ固有の挙動は [README §6](./README.md#6-本仕様と画面デモの差異明記) を参照。

## 1. 概要
- 目的：巡回の**実施後に気付いたこと**を、記録本体を書き換えずに追加していく。
- 背景：実施後に補足したいケースがあり、**その内容・登録時刻・登録ユーザーを残したい**という要望に基づく。
- 配置：[02 巡回パトロール詳細](./02-巡回パトロール詳細.md)の「作業所コメント」の下。
- 利用ロール：**元請・協力会社のいずれも登録できる**。
- 対象：**実施済みの書類**（＝ステータスが「巡回済み」「元請確認済み」のいずれも対象）。元請確認の前後を問わない。

### 中心となる業務ルール
| ルール | 内容 |
|---|---|
| A-1 | 元請・協力会社のどちらのユーザーも、テキストと添付ファイルを**自由に追加できる**。 |
| A-2 | 追記には**登録日時と登録ユーザー**を記録する。編集した場合は**更新日時**も記録する。 |
| A-3 | **編集・削除ができるのは、その追記を登録したユーザー本人のみ。** |
| A-4 | 追記は記録本体（チェック項目の回答・所見・作業所コメント）を書き換えない。独立した追加情報として保持する。 |

## 2. 画面要素
- セクション見出し「追記」と、ルールの説明文。
- 登録済み追記の一覧（登録順）。1件ごとに：
  - ヘッダー：登録者名／所属（元請・協力会社）／自分の追記である旨の表示／**登録日時**（編集済みなら**更新日時**も）／編集・削除ボタン（本人のみ）
  - 本文テキスト
  - 添付ファイル（§3.2）
- 新規登録フォーム（常時表示）：ログイン中のユーザー名の明示、本文入力欄、ファイル添付、登録ボタン。
- 削除時の確認ダイアログ。

## 3. 表示項目 / 入力項目

### 3.1 追記のデータ項目
| 項目 | 内容 | 必須 | 備考 |
|---|---|---|---|
| 登録者 | ユーザーID・氏名・ロール（所属） | ○ | **認証情報から決定**（クライアント値を信用しない） |
| 登録日時 | 追記を登録した日時 | ○ | サーバ時刻。分単位表示（想定） |
| 更新日時 | 最後に編集した日時 | — | 未編集なら空。表示は「登録◯◯／更新◯◯」 |
| 本文 | テキスト（改行可） | △ | 添付ファイルがあれば省略可（§7） |
| 添付ファイル | 0件以上 | △ | 本文があれば省略可（§7） |

### 3.2 添付ファイルの表示
| 種別 | 表示 |
|---|---|
| **画像ファイル** | **小さめのサムネイル**で表示し、**クリックで拡大ダイアログ**を開く。ダイアログにはファイル名・拡大画像・ダウンロード・閉じるを備える |
| 画像以外（PDF・文書など） | ファイル名＋ファイルサイズのリンクとして表示し、クリックでダウンロード |

- 画像かどうかの判定は MIMEタイプを基準とする（拡張子のみで判定しない）。
- 編集中も同じサムネイル表示とし、ファイル単位で削除できる。
- サムネイルの**サイズ・並び順・表示上限はエンジニアマター**（決定事項 D-36）。実装側で決定し本書に反映すること。
- **拡大ダイアログでは前後の画像に送れるようにする**（決定事項 D-37）。
  - 対象は**同じ追記に添付された画像**。前へ／次へのボタンと現在位置（例：2 / 3）を表示し、キーボードの左右キーでも移動できる。先頭・末尾では対応するボタンを無効にする。
- **画像以外（PDF・文書など）はプレビューせず、ダウンロードのみ**とする（決定事項 D-38）。

## 4. 機能・操作

| 操作 | 実行できるユーザー | 内容 |
|---|---|---|
| 登録 | 元請・協力会社（閲覧できる記録に対して） | 本文・添付ファイルを指定して追記を追加 |
| 編集 | **登録者本人のみ** | 本文・添付ファイルを更新。更新日時を記録 |
| 削除 | **登録者本人のみ** | 追記と添付ファイルを削除。**確認ダイアログを経由**する |
| 閲覧 | 記録を閲覧できるユーザー全員 | 他ユーザーの追記も閲覧できる |

- 本人以外には編集・削除の操作を表示しない。
- **表示制御だけでなく、API側でも登録者本人であることを検証する**（[README §5.2](./README.md)）。
- 追記の登録時に**関係者への通知は行わない**（決定事項 D-11）。[01 一覧](./01-巡回パトロール一覧.md)の追記カラムで有無を確認する運用とする。

- **管理者による代行削除の機能は提供しない**（決定事項 D-6）。本人以外は元請であっても削除できない。不適切な追記や退職者の追記をどうしても消す必要が生じた場合は、**運用として開発側へ削除を依頼する**（データ直接操作）。まずはこの運用で様子を見る。
- 編集・削除に**期限は設けない**（決定事項 D-8）。登録者本人であれば、いつでも編集・削除できる。
- **追記へのリプライ（スレッド化）は提供しない**（決定事項 D-34）。フラットな一覧とする。

## 5. 状態・ロール別表示差
- ステータス（巡回済み／元請確認済み）による**差はない**。どちらでも登録・編集・削除できる。
- 自分が登録した追記には、本人であることがわかる表示を付ける。
- **記録を閲覧できるユーザーには、他社ユーザーの追記も見せる**（決定事項 D-35）。追記の閲覧範囲は記録の閲覧範囲と同じ。

## 6. データ・外部連携
- 追記は巡回記録に1対多で紐づく。
- 添付ファイルはオブジェクトストレージに保存し、権限付きURLで配信する（[README §5.4](./README.md)）。
- 削除は**論理削除**とする（決定事項 D-9）。画面・帳票・一覧の追記カラムからは除外し、レコードは残す。
  - 添付ファイルの実体も併せて残す（論理削除のため即時削除しない）。保持期間は運用で決める。

## 7. バリデーション・制約
| 対象 | ルール |
|---|---|
| 登録・更新 | **本文・添付ファイルの少なくとも一方が必要**（両方空では登録できない） |
| 本文 | 文字数上限は**エンジニアマター**（[02 D-33](./02-巡回パトロール詳細.md)） |
| 添付ファイル | 許可拡張子・MIME・1ファイルの最大サイズ・件数上限は**実装側の裁量で定める**（決定事項 D-10） |
| 権限 | 編集・削除は登録者本人のみ（サーバ側で検証） |

- 添付ファイルの制限値・ウイルススキャンの要否は**エンジニアマター**として実装側で決定する（D-10）。決めた値は本ドキュメントに追記すること。

## 8. 例外・エッジケース
- 同一の追記を別端末で同時に編集した場合の競合。
- 添付ファイルのアップロード中に通信が切れた場合の扱い（部分登録を残さない）。
- 大きな画像（スマホ撮影の原寸）を複数添付した場合の表示・転送量。
- 削除された追記を参照していた印刷帳票・通知との整合。
- 登録者が現場から外れた／退職した後の追記の扱い（編集・削除ができなくなる）。

## 決定事項（回答済み）
- **D-6 管理者による代行削除は提供しない**（§4）。編集・削除は登録者本人のみ（A-3）を維持する。例外対応は開発側への削除依頼で行い、運用しながら要否を再判断する。
  - 実装上の含意：**削除依頼を受けられるよう、追記は記録ID・登録者・登録日時から特定できる形で保持すること**。
- **D-7 一覧に追記の有無カラムを追加する**（[01 §3.1](./01-巡回パトロール一覧.md)）。有無のみで、件数は出さない。
- **D-8 編集・削除に期限を設けない**（§4）。
- **D-9 削除は論理削除**（§6）。物理削除しない。
- **D-10 添付ファイルの制限値・ウイルススキャンはエンジニアマター**（§7）。実装側で決定し、決定値を本書に反映する。
- **D-11 追記の登録を関係者へ通知しない**（§4）。一覧の追記カラム（[01 §3.1](./01-巡回パトロール一覧.md)）で気付ける形とする。
- **D-12 印刷帳票に追記を含める**（[02 §4.3](./02-巡回パトロール詳細.md)）。
- **D-34 追記のスレッド化（リプライ）は提供しない**（§4）。
- **D-35 他社ユーザーの追記も閲覧できる**（§5）。閲覧範囲は記録の閲覧範囲と同じ。
- **D-36 サムネイルのサイズ・並び順・表示上限はエンジニアマター**（§3.2）。
- **D-37 拡大ダイアログで前後の画像に送れるようにする**（§3.2）。
- **D-38 画像以外はプレビューせずダウンロードのみ**（§3.2）。
