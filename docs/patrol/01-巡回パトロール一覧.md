# 01. 巡回パトロール一覧（`/patrol/records`）

> ステータス：ドラフト／要レビュー
> 本番で想定される仕様を記載する。デモ固有の挙動は [README §6](./README.md#6-本仕様と画面デモの差異明記) を参照。

## 1. 概要
- 目的：現場で作成された巡回/パトロール記録を一覧し、**元請確認が必要な記録を見つけて詳細へ入る**。
- 利用ロール：元請／協力会社（データスコープは要確定。[README §4](./README.md)）。
- アクセス経路：巡回/パトロールのサイドメニュー「巡回パトロール一覧」。
- 対応デバイス：PC を主、スマホ・タブレットでも閲覧可（狭幅ではテーブルに代えてカード表示）。

### 重要な前提
**この画面から巡回記録は作成できない。** 記録は現場のQRコードを読み取ったユーザーのみが作成する（[04](./04-巡回パトロール実施用QR発行.md)）。
そのため**新規作成ボタンは設けず**、その旨を画面上の案内文で明示する。

## 2. 画面要素
- 見出し：「巡回/パトロール記録・予定」。
- 案内文：QR読み取りでのみ作成される旨（常時表示）。
- 検索条件エリア：キーワード／実施会社／一次会社、「検索」「クリア」。
- 巡回月の切替：`＜ YYYY年M月 ＞`（前月・翌月送り、月選択）。
- ステータス凡例：「元請確認済み」「巡回済み」（**表示のみ。絞り込み操作ではない**）。
- CSVファイル出力ボタン。
- 一覧テーブル（狭幅時はカード）。
- ページネーション（ページあたりの行数：25／50／100、既定50）。

## 3. 表示項目 / 入力項目

### 3.1 一覧の列
| 列 | 内容 | 備考 |
|---|---|---|
| ステータス | 巡回済み／元請確認済み | §5.1 |
| 予定日 | 次回巡回の予定として登録された日付 | 未設定は空欄 |
| 実施日 | 巡回を実施した日付 | |
| 実施会社 | 巡回を実施した会社 | |
| 一次会社 | 実施会社の一次請 | |
| 実施者 | 巡回を実施した担当者名 | |
| 次回予定日 | 記録に登録された次回予定日 | 未設定は空欄 |
| 写真添付 | 写真ありは「あり」（強調表示）、無しは「－」 | 巡回時の指摘写真の有無 |
| **追記** | **追記が1件以上あれば「あり」、無ければ「－」** | 実施後に追加された情報の有無（[03](./03-追記.md)） |
| 詳細 | 詳細画面へのボタン | [02](./02-巡回パトロール詳細.md) |

#### 追記カラムの仕様
- 判定：その巡回記録に紐づく**追記の件数が1件以上か**のみ。件数や内容は一覧に出さない。
- 表示：「あり」／「－」。
- **写真添付とは強調度を変える**。写真添付は現場対応が必要な指摘を示すため強調色（赤）、追記は補足情報のため通常色とする。
- 追記の登録・削除に追従して即時に切り替わる。
- 追記の有無による**絞り込みは提供しない**。表示のみとする（決定事項 D-19）。
- **件数は表示しない**。有無のみ（決定事項 D-19）。

#### 並び順
- 既定は**実施日の昇順**（決定事項 D-20）。
- 実施日を持たない行（予定のみ）は**予定日で並べる**（想定）。
- **同日内は巡回記録No.順**（決定事項 D-49）。
- **列ごとの並び替え操作を提供する**（決定事項 D-50）。見出しをクリックで昇順／降順を切り替える。

#### 予定のみの行
- 予定だけが登録され、まだ実施されていない記録も**一覧に表示する**（決定事項 D-21）。
- ステータスは**「未」**（§5.1）。実施日・写真添付・ヒアリング等は空になる。

**生成経路（決定事項 D-40）**
QR読み取り後の巡回実施入力画面で**「次回予定日」を入力すると、その日付を予定日とする記録が自動生成される**。
一覧から予定を直接登録する導線は無い。

```
巡回記録A（実施日 3/05・次回予定日 3/20）
        │ 次回予定日の入力により自動生成
        ▼
巡回記録B（予定日 3/20・実施日なし・ステータス「未」）
        │ 実際に巡回して入力
        ▼
巡回記録B（実施日が入り「巡回済み」へ）
```

- 生成される記録は**独自の巡回記録No.を持つ**。
- **実施会社・実施者は引き継ぐ。一次会社は引き継がない**（決定事項 D-82）。現行システムの挙動に合わせる。
  - 一次会社は巡回を実施したときに入力される（予定の段階では空欄）。
- **予定日を過ぎても実施されなかった記録は、ステータス「未」のまま残り続ける**（決定事項 D-51）。自動での消去・アラートは行わない。
- **予定の記録は編集できない**（予定日の変更不可）。**削除はArchの管理者権限でのみ可能**で、ユーザーは削除できない（決定事項 D-83）。

### 3.2 検索条件
| 項目 | 形式 | 対象 |
|---|---|---|
| キーワード | テキスト（部分一致） | 巡回記録No.／実施会社／一次会社／実施者／同行者／所見（想定） |
| 実施会社 | プルダウン（単一選択） | **登録済みの巡回記録が持つ実施会社の値**（重複を除いたもの） |
| 一次会社 | プルダウン（単一選択） | **登録済みの巡回記録が持つ一次会社の値**（重複を除いたもの） |

- 一次会社は巡回実施時の**自由入力**（[07 D-48](./07-巡回実施入力.md)）のため、選択肢を固定の会社マスタから作ると入力値と一致せず絞り込めなくなる。**実際に登録された値から選択肢を作る**こと。

- 「検索」で条件を確定し、結果とページングをリセットする。
- 「クリア」で条件を初期化し、再検索する。
- [ ] ⚠️ キーワードの検索対象（上記は想定）。**エンジニアマターとして実装側で確定する**（決定事項 D-22）。決めた対象を本書に反映すること。

#### 検索条件・巡回月の保持（決定事項 D-23）
| 戻り方 | 巡回月 | 検索条件 |
|---|---|---|
| **ブラウザバック** | **保持** | **保持** |
| 詳細画面の**「一覧へ戻る」ボタン** | **保持** | **初期化** |

- 「一覧へ戻る」は巡回月だけを引き継ぎ、検索条件をクリアした状態で一覧を表示する。
- **ページング（表示中のページ）は保持しない**（決定事項 D-88）。保持するのは巡回月と検索条件のみ。
- **巡回月の初期値は当月**（決定事項 D-52）。

## 4. 機能・操作
| 操作 | 内容 | 権限 |
|---|---|---|
| 検索／クリア | 条件で絞り込む | 全ロール |
| 巡回月の切替 | 前月・翌月・月指定 | 全ロール |
| 詳細へ遷移 | 詳細ボタンから記録を開く | 全ロール（スコープ内） |
| CSV出力 | **絞り込み後の全件**を出力 | 元請・協力会社（決定事項 D-24） |
| 新規作成 | **提供しない**（QR経由のみ） | — |

### CSV出力
- 出力対象：**画面の絞り込み結果の全件**（表示中のページだけではない）。
- 実行できるロール：**元請・協力会社のいずれも可**（決定事項 D-24）。協力会社は自身のデータスコープ内が対象。
- 文字コード：**UTF-8（BOM付き）**。Excelで文字化けしないこと。
- ファイル名：`YYYY年M月分巡回記録・予定_現場名.csv`。
- 件数上限・非同期出力は設けない（決定事項 D-25）。

#### 出力フォーマット（決定事項 D-25）
固定列のあとに、巡回項目が「項目N」「項目Nコメント」の組で続く。

| # | 列 | 内容 |
|---|---|---|
| 1 | 予定日 | 空の場合あり |
| 2 | 実施日 | 未実施なら空 |
| 3 | 実施会社 | |
| 4 | 一次会社 | |
| 5 | 実施者 | |
| 6 | 次回予定日 | 空の場合あり |
| 7 | 写真添付 | `あり` ／ `－` |
| 8 | 元請確認 | **`済` ／ `未`**（一覧のステータス表記とは異なる） |
| 9 | ヒアリング・所見 | 本文 |
| 10 | 詳細 | **巡回記録詳細のURL** |
| 11〜 | 項目1, 項目1コメント, 項目2, 項目2コメント, … | 評価とコメントの組 |

- 「項目N」の列数は、**出力対象のうち最大の項目数**に合わせる。項目数が少ない記録の余った列は空にする。
- 「項目N」には評価値をそのまま出力する（評価の選択肢はユーザー設定。[02 D-16](./02-巡回パトロール詳細.md)）。
- **追記は出力に含めない**（決定事項 D-39）。件数が可変で列が際限なく増えるため。
- **是正内容もCSVに出力しない**（決定事項 D-53）。追記と同じく、項目ごとに列が増えるため。

## 5. 状態・ロール別表示差

### 5.1 ステータス
| ステータス | 条件 | 表示 |
|---|---|---|
| **未** | 予定だけが登録され、**まだ実施されていない** | 未実施であることがわかる表示 |
| 巡回済み | 記録が作成され、元請確認が未実施 | 強調（対応待ち） |
| 元請確認済み | 元請確認が完了している | 完了扱いの表示 |

- 「未」の判定は**実施日の有無**、「元請確認済み」の判定は**元請確認日の有無**で行う。
- ステータスは上記2種類のみとする。**是正状況（是正待ち／是正済み）はステータスとして持たない**（決定事項 D-1）。

### 5.2 ロール別
- 元請：現場の全記録を閲覧。
- **協力会社：現場の全記録を閲覧できる**（決定事項 D-85）。自社分への絞り込みは行わない。
- 協力会社にも「元請確認済み」ステータスを**見せる**（決定事項 D-26）。

## 6. データ・外部連携
- 巡回記録は現場（工事番号）に属する。
- 実施会社・一次会社は巡回記録が持つ値をそのまま使う（一次会社は実施時の自由入力。[07 D-48](./07-巡回実施入力.md)）。
- **他システムとの同期は行わない**（決定事項 D-27）。

## 7. バリデーション・制約
- 絞り込み結果が0件の場合はその旨を表示する。
- CSV出力は0件時に実行させない（またはヘッダーのみ出力するかを要確定）。
- **巡回月の選択可能範囲に制限は設けない**（決定事項 D-28）。過去・未来のいずれにも際限なく送れる。

## 8. 例外・エッジケース
- 対象月に記録が無い。
- 権限スコープ外の記録IDを直接URL指定された場合 → 403 相当（サーバ側で判定）。
- 一覧表示中に他ユーザーが元請確認を完了した場合のステータス不整合（再取得のタイミング）。

## 決定事項（回答済み）
- **D-1 是正状況のステータスは不要**。是正済みかどうかは一覧では判別しない（詳細画面で確認する）。
- **D-2 追記の有無を示すカラムを追加する**（§3.1）。有無のみを「あり／－」で表示する。
- **D-19 追記カラムは絞り込み条件にせず、件数も出さない**（§3.1）。
- **D-20 並び順は実施日の昇順**（§3.1）。
- **D-21 予定のみ（未実施）の行も一覧に表示し、ステータスは「未」**（§3.1・§5.1）。
- **D-22 キーワードの検索対象はエンジニアマター**（§3.2）。実装側で確定し本書へ反映する。
- **D-23 ブラウザバックは巡回月・検索条件とも保持。「一覧へ戻る」ボタンは巡回月のみ保持**（§3.2）。
- **D-24 CSV出力は協力会社も可能**（§4）。
- **D-25 CSVの出力フォーマットを確定**（§4）。件数上限・非同期出力は設けない。
- **D-26 協力会社にも「元請確認済み」ステータスを見せる**（§5.2）。
- **D-27 会社マスタの他システム同期は行わない**（§6）。
- **D-28 巡回月の選択範囲に制限を設けない**（§7）。
- **D-48 実施会社・一次会社の絞り込み選択肢は、登録済みの記録が持つ値から作る**（§3.2）。一次会社が自由入力のため。
- **D-49 同日内の並び順は巡回記録No.順**（§3.1）。
- **D-50 列ごとの並び替え操作を提供する**（§3.1）。
- **D-51 予定日を過ぎた「未」の記録は残り続ける**（§3.1）。自動消去・アラートなし。
- **D-52 巡回月の初期値は当月**（§3.2）。
- **D-53 是正内容はCSVに出力しない**（§4）。
- **D-82 予定の記録は実施会社・実施者を引き継ぐ。一次会社は引き継がない**（§3.1）。現行システムの挙動どおり。
- **D-83 予定の記録は編集不可。削除はArchの管理者権限のみ**（§3.1）。ユーザーは削除できない。
- **D-85 協力会社も現場の全記録を閲覧できる**（§5.2）。データスコープの制限は設けない。
- **D-88 一覧のページングは保持しない**（§3.2）。
- **D-39 追記はCSVに出力しない**（§4）。件数が可変で列が際限なく増えるため。
- **D-40 予定のみの記録は、巡回実施入力画面の「次回予定日」から自動生成される**（§3.1）。
