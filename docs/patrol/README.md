# 巡回/パトロール 詳細仕様 — 枠組み

> ステータス：**ドラフト（要レビュー）**
> 目的：本ドキュメント一式を用いて、詳細仕様を engineer に伝え、**要件の認識相違をなくす**。
> 位置づけ：**本番で想定される機能の仕様**を記載する。画面デモ（`/patrol`）は要件確認用のモックであり、デモ固有の挙動は仕様ではない（差異は §5 に明記）。
> 使い方：各 md の「⚠️ 未決事項・考慮不足（要確認）」を中心に、○×・補足を記入してください。**（想定）** と記した箇所は現時点の想定であり、確定仕様ではありません。

## 0. このドキュメントの読み方

- 画面・機能ごとに md を用意。作業間調整Pro（`docs/workadjust`）と同じテンプレートに沿う。
- 記号の意味：
  - **（想定）** … 現時点の想定。要確認。
  - **⚠️** … 未決／考慮不足。実装前に必ず合意が必要な点。
  - `[ ]` … 決定・記入いただきたいチェック項目。

### 共通テンプレート

1. 概要（目的・利用ロール・アクセス経路・対応デバイス）
2. 画面要素（レイアウト・主要UI）
3. 表示項目 / 入力項目（列・フォーム・必須/初期値/データソース）
4. 機能・操作（アクション一覧・ロール別可否）
5. 状態・ロール別表示差
6. データ・外部連携
7. バリデーション・制約
8. 例外・エッジケース
9. ⚠️ 未決事項・考慮不足（要確認）

## 1. 機能の全体像

現場の安全巡回（パトロール）を記録し、元請が内容を確認して是正を回していくための機能。

```
QRコード掲示（現場）
   │  読み取り（ログイン必須 / ログイン不要 の2種）
   ▼
巡回実施入力 ──登録──▶ 巡回記録（ステータス：巡回済み）
                            │
                            │ 「次回予定日」を入力していた場合
                            ├──▶ 次回の巡回記録（ステータス：未）
                            │      実施されると「巡回済み」になる
                            │
                            │ 元請ユーザーが内容を確認
                            │ ・作業所コメント（必須）
                            │ ・是正内容（任意）
                            ▼
                        ステータス：元請確認済み
                            │
                            ├─ 是正入力：確認後もいつでも何度でも可（元請のみ）
                            └─ 追記：テキスト＋添付ファイルを随時追加（元請・協力会社とも可／登録者のみ編集・削除可）
```

**重要な前提：巡回記録は QRコードを読み取ったユーザーだけが作成する。**
一覧画面に新規作成の導線は設けない（[01](./01-巡回パトロール一覧.md) §4）。

**予定（ステータス「未」）の記録は、巡回実施入力画面で「次回予定日」を入力した結果として自動生成される**（[01 D-40](./01-巡回パトロール一覧.md)）。一覧から予定を直接登録する導線は無い。

| 詳細の閲覧 | ○ | ○（現場の全件） | × |
| 元請確認の実施 | ○ | × | × |
| 作業所コメントの入力 | ○（確認時のみ・必須） | × | × |
| 作業所コメントの編集 | **×（確認後は編集不可）** | × | × |
| 元請確認の取り消し・差し戻し | **×（誰も不可）** | × | × |
| 是正入力（元請確認前） | ○ | **×** | × |
| 是正入力（元請確認後） | ○（何度でも） | **×** | × |
| 追記の登録 | ○ | ○ | × |
| 追記の編集・削除 | ○（**自分が登録した追記のみ**。他人の追記は元請でも不可） | ○（**自分が登録した追記のみ**） | × |

| 印刷 | ○ | ○ | × |

## 5. 横断的な未決事項・考慮不足（**全画面共通で要確認**）

### 5.1 認証・ロール・データスコープ
- ログイン／認証方式・ロールの判定元は**エンジニアマター**（決定事項 D-89）。
- **本機能では協力会社マスタとの紐付けは行わない**（決定事項 D-86）。データスコープによる絞り込みもないため（D-85）、紐付けは不要。
- **巡回記録は現場（工事番号）に属する**（決定事項 D-87）。

### 5.2 権限のサーバ側担保
- [ ] ⚠️ **画面制御だけでなくAPI側でも権限を検証すること**。特に以下は改ざんされると業務上の意味が壊れる。
  - 元請確認は元請ユーザーのみ
  - 作業所コメントは確認後に更新不可（**サーバ側で不変を保証**）
  - 追記の編集・削除は登録者本人のみ（`authorId` を**リクエスト値ではなく認証情報から**決定）

### 5.3 データ永続化・履歴
- 監査ログ・変更履歴は**エンジニアマター**（決定事項 D-90）。
- [x] 是正内容は**上書き保存・履歴なし**（[02 D-3](./02-巡回パトロール詳細.md)）。**「何度でも可」のため、上書きすると過去の是正内容は復元できない**点に留意して実装すること。
- [x] 追記の削除は**論理削除**（[03 D-9](./03-追記.md)）。**一覧・詳細・帳票からは除外し、レコードと添付ファイルの実体は残す**。
- 同時編集・排他制御は**エンジニアマター**（決定事項 D-91）。

### 5.4 ファイル・画像
- [x] 添付ファイルの**許可拡張子・MIME・最大サイズ・件数上限・ウイルススキャン**は実装側の裁量で決定（[03 D-10](./03-追記.md)）。決定値は [03 §7](./03-追記.md) に反映すること。
- 添付ファイルの保存先・署名付きURLの有効期限・直リンクの権限チェックは**エンジニアマター**（決定事項 D-79）。
- 写真のEXIFの扱い・画像の自動リサイズ／サムネイル生成は**エンジニアマター**（決定事項 D-79）。

### 5.5 通知・帳票
- [x] **通知は行わない**（D-18）。巡回記録の登録・元請確認の依頼／完了・是正の督促・追記のいずれも通知しない。一覧画面で状況を確認する運用とする。
- [x] 巡回記録の印刷帳票は**A4縦・専用レイアウト・追記を含む**（[02 §4.3](./02-巡回パトロール詳細.md)）。
- **押印運用・保管要件は無し**（決定事項 D-80）。
- [x] 巡回チェック項目のマスタ・評価の選択肢の設定画面は、**「巡回/パトロール項目編集」（05）「巡回/パトロール回答編集」（06）として設ける**（D-32・D-41）。**画面の詳細仕様は後日定義**。**評価値をコードに固定しないこと**（D-16）。
  - 05：巡回時にチェックする項目の登録・編集。ここで設定した項目が巡回記録の「巡回項目」になる。
  - 06：巡回項目に対する回答（評価）の選択肢の登録・編集。現場ごとに設定できる（D-16）。
  - **どちらも元請のみ。協力会社にはメニューを出さず、URL直打ちでも閲覧させない**（サーバ側でも権限を検証すること）。
- [x] 05・06 の画面仕様を [05](./05-巡回パトロール項目編集.md)・[06](./06-巡回パトロール回答編集.md) に記載（D-42）。
- [x] **マスタ変更と過去の巡回記録の関係は決定済み**（D-64）。巡回記録は**実施時点の項目文・評価値を自分のデータとして保持**し、マスタを変更・削除しても過去の記録・帳票・CSVは変わらない。

### 5.6 日付・タイムゾーン
- 日付・日時の基準（端末ローカルか現場基準か）は**エンジニアマター**（決定事項 D-81）。
- **記録の対象日（実施日）は当日固定**（[07 D-76](./07-巡回実施入力.md)）。遡っての登録はできない。

## 6. 本仕様と画面デモの差異（明記）

画面デモ（`/patrol`・`/no-account/owner-patrol`）は要件確認用のモック。以下はデモ固有であり、**本番仕様ではない**。

| デモの挙動 | 本番で想定する仕様 |
|---|---|
| ヘッダーの「元請／協力会社」トグルでロールを切替 | 認証情報からロールを判定 |
| ログインユーザーはロールごとに固定の1名 | 実ユーザー（ID・氏名・所属会社） |
| データはブラウザ内 state。リロードで初期化 | DB／API に永続化 |
| 添付ファイルは `URL.createObjectURL` でブラウザ内のみ保持 | オブジェクトストレージへ保存（§5.4） |
| 巡回チェック項目はサンプル固定 | 現場ごとに設定されたチェック項目マスタから取得 |
| 元請確認日は操作端末の当日日付 | サーバ時刻 |
| 権限はUI表示のみで制御 | **API側でも検証**（§5.2） |
| 巡回記録の作成画面（QR読み取り後）は未実装のスタブ | 別途実装が必要（§2） |
