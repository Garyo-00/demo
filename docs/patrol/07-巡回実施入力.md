# 07. 巡回実施入力（QR読み取り後）

> ステータス：ドラフト／要レビュー
> 本番で想定される仕様を記載する。デモ固有の挙動は [README §6](./README.md#6-本仕様と画面デモの差異明記) を参照。

## 1. 概要
- 目的：現場に掲示したQRコードを読み取ったユーザーが、**巡回記録を作成する**。
- 位置づけ：**巡回記録の唯一の作成経路**。一覧画面からは作成できない（[01 §1](./01-巡回パトロール一覧.md)）。
- 利用ロール：巡回実施者。**サイドバーは表示せず、スマホでの入力を主とする単独ページ**。
- アクセス経路：[04 QRコード](./04-巡回パトロール実施用QR発行.md)の読み取り。**ログイン必須／ログイン不要の2種**があり、種別で入力のされ方が変わる（§3.1）。
- 確認項目と回答の選択肢は、**設定画面のマスタから組み立てる**（[05](./05-巡回パトロール項目編集.md)・[06](./06-巡回パトロール回答編集.md)）。

## 2. 画面要素
上から順に：
1. 現場名（見出し）／**実施日**（当日）
2. 案内：「画面一番下の［一時保存］ボタンより入力内容を保存できます。」
3. 実施会社／一次会社／実施者（§3.1）
4. 同行会社・名前（任意）
5. 帯「写真」＋「写真を追加」＋**枚数表示（n / 30 枚）**
6. 帯「確認項目」＋項目ごとの回答（§3.2）
7. 帯「ヒアリング・所見」＋コメント入力（**必須／任意は [06 §3.2](./06-巡回パトロール回答編集.md) の設定に従う**）
8. 帯「次回巡回予定」＋日付＋「今回で最後」チェック
9. 最下部：**一時保存／読込／登録**

## 3. 表示項目 / 入力項目

### 3.1 実施会社・一次会社・実施者
| 項目 | 値 |
|---|---|
| 実施日 | **当日固定**（サーバ時刻）・表示のみ。遡っての登録はできない（決定事項 D-76） |
| 実施会社 | ログイン必須QR：**実施ユーザーの登録会社名**（本番は `users.company_name`）・表示のみ（D-70）／ログイン不要QR：**入力欄**（D-84） |
| **一次会社** | **入力欄**（§ QR種別による違い） |
| 実施者 | ログイン必須QRでは表示のみ、ログイン不要QRでは入力欄 |

#### QR種別による違い（決定事項 D-43・D-47）
| QR種別 | 一次会社 | 実施者 |
|---|---|---|
| **ログイン必須** | **入力欄**。ログインユーザーの**所属会社を初期値として表示**し、**必要なら変更できる**（D-43） | ログインユーザーの氏名を**自動表示**（変更不可） |
| **ログイン不要** | **空欄の入力欄**（手入力）（D-47） | **空欄の入力欄**（手入力）（D-47） |

※ **実施会社**も、ログイン必須QRでは `users.company_name` を表示、**ログイン不要QRでは空欄の入力欄**とする（D-84）。

- 一次会社は**どちらの種別でも入力欄**とする。実施者の所属と一次会社が一致しない場合（応援・下請の立場で巡回する等）に備え、初期値は入れつつ変更を許す。
- ログイン不要の場合はユーザーを特定できないため、一次会社・実施者とも空欄で手入力させる。
- **一次会社・実施者はいずれも必須入力**（決定事項 D-71）。
- **一次会社は自由入力**とする（決定事項 D-48）。協力会社マスタからの選択にはしない。
  - 表記ゆれが起きうるため、**一覧の一次会社・実施会社の絞り込みは、固定マスタではなく登録済みの記録が持つ値から選択肢を作る**（[01 §3.2](./01-巡回パトロール一覧.md)）。自由入力された会社名でも絞り込めるようにするため。
- **実施会社は実施ユーザーの登録会社名（`users.company_name`）を適用する**（D-70）。固定値にはしない。
- **ログイン不要QRの場合は `users.company_name` を引けないため、実施会社も入力させる**（決定事項 D-84）。必須入力。

### 3.2 確認項目
- [05 項目編集](./05-巡回パトロール項目編集.md)のマスタを**登録順に連番付きで**表示する。
- 回答は [06 回答編集](./06-巡回パトロール回答編集.md)の選択肢を**ラジオボタンで横並び**に出す（単一選択）。
- 選んだ選択肢が「追加入力」ONの場合、その下に**追加入力欄**を表示する。プレースホルダは「『（選択肢名）』の追加入力」。
- 「必須」ONの選択肢を選んだ場合、追加入力は**必須**。
- 入力された追加入力は、巡回記録の項目コメントになる（[02 §3.2](./02-巡回パトロール詳細.md)）。

### 3.3 写真
- 「写真を追加」で端末から選択。**上限30枚**。現在の枚数を `n / 30 枚` で表示する。
- 写真ごとに**コメント**を入力できる。これが巡回記録の写真キャプション（指摘内容）になる。
- 枚数上限・1枚あたりのサイズ上限は**エンジニアマター**（決定事項 D-72）。実装側で決定し本書に反映すること。

### 3.4 次回巡回予定
- 日付を入力すると、**その日付を予定日とする巡回記録が自動生成される**（[01 D-40](./01-巡回パトロール一覧.md)）。ステータスは「未」。
- **「今回で最後」**にチェックを入れると日付入力を無効化し、予定を作らない。
- 生成される予定は**実施会社・実施者を引き継ぎ、一次会社は引き継がない**（[01 D-82](./01-巡回パトロール一覧.md)）。

## 4. 機能・操作

### 4.1 一時保存・読込
- **一時保存**：入力内容を保存する。現場では通信が不安定なため、登録前に退避できるようにする。
- **読込**：一時保存した内容を画面に戻す。
- **保存先はサーバ**（決定事項 D-73）。
- **保存単位はユーザー単位**。同じユーザーが次に巡回実施入力を開いたとき、「読込」ボタンを押すと一時保存データがあれば読み込まれる。
- **保持期間は無期限**。
- 読込時の確認ダイアログは設けない（ボタンを押した時点で読み込む）。

### 4.2 登録
1. **入力チェック**（§7）。エラーがあれば登録せずメッセージを表示する。
2. **確認ダイアログ**を表示する（決定事項 D-44）。
3. ダイアログの「登録」で巡回記録を作成し、**巡回記録の一覧へ移動する**（D-44）。
4. 「キャンセル」で入力画面に戻る（入力内容は保持）。

#### 確認ダイアログの内容
- タイトル「巡回記録登録の確認」／「入力内容で巡回記録を登録しますか？」
- **入力内容確認**：実施会社／一次会社／実施者／同行会社・名前／ヒアリング・所見／次回巡回予定（未入力は「なし」）
- **確認項目（N件）**：連番・項目文・選んだ回答。追加入力があれば「コメント: …」を併記
- **写真（N件）**：サムネイルとコメント
- ボタン：登録／キャンセル

- 登録後の遷移先は**巡回記録の一覧**。登録した記録が見えるよう、**一覧の巡回月は実施日の月に合わせる**。

## 5. 状態・ロール別表示差
- 作成専用の画面で、既存記録の編集には使わない。
- 登録後は一覧・詳細で扱う（元請確認・是正入力・追記は [02](./02-巡回パトロール詳細.md)・[03](./03-追記.md)）。

## 6. データ・外部連携
- 作成される巡回記録の項目は、**実施時点の項目文と回答値を記録側に保持する**想定（[05 §6](./05-巡回パトロール項目編集.md)・[06 §6](./06-巡回パトロール回答編集.md)）。マスタを後から変えても過去の記録が変わらないようにするため。
- 巡回記録No.は登録時に採番する（[02 D-29](./02-巡回パトロール詳細.md)）。

## 7. バリデーション・制約
| 対象 | ルール |
|---|---|
| 確認項目 | **すべての項目に回答が必要**（想定・要確認） |
| 一次会社 | **必須入力**（種別を問わず） |
| 実施者 | ログイン不要QRの場合は**必須入力**（D-47） |
| 実施会社 | ログイン不要QRの場合は**必須入力**（D-84） |
| ヒアリング・所見 | [06 §3.2](./06-巡回パトロール回答編集.md) で**必須回答**に設定されている場合は入力必須（D-46） |
| 追加入力 | 選んだ選択肢が「必須」の場合は入力必須 |
| 写真 | 30枚まで |
| 次回巡回予定 | 「今回で最後」と同時には入力できない |

- **確認項目は全項目回答必須**（決定事項 D-74）。
- **二重登録を防ぐ機能は設けない**（決定事項 D-75）。

## 8. 例外・エッジケース
- 通信断・アップロード失敗（写真が多いと起こりやすい）。一時保存で救済できるようにする。
- 入力途中にマスタ（項目・選択肢）が変更された場合。
- 現場の稼働期間外にQRが読み取られた場合（[04](./04-巡回パトロール実施用QR発行.md)）。

## 決定事項（回答済み）
- **D-43 ログイン必須QRでは、一次会社の入力欄に実施ユーザーの所属会社を初期表示する。変更も可能**（§3.1）。
- **D-44 登録時は確認ダイアログを挟み、登録後は巡回記録の一覧へ遷移する**（§4.2）。
- **D-47 ログイン不要QRでは、一次会社・実施者を空欄の入力欄で表示する**（§3.1）。
- **D-48 一次会社は自由入力**（§3.1）。マスタからの選択にはしない。
- **D-70 実施会社は実施ユーザーの登録会社名（`users.company_name`）を適用する**（§3.1）。
- **D-71 一次会社・実施者は必須入力**（§3.1）。
- **D-72 写真の枚数・サイズ上限はエンジニアマター**（§3.3）。
- **D-73 一時保存はサーバに保存。ユーザー単位・無期限。「読込」で復元する**（§4.1）。
- **D-74 確認項目は全項目回答必須**（§7）。
- **D-75 二重登録の防止機能は設けない**（§7）。
- **D-76 実施日は当日固定**（§3.1）。遡って登録できない。
- **D-84 ログイン不要QRでは実施会社も空欄の入力欄とし、必須入力とする**（§3.1）。
