# 06. 巡回/パトロール回答編集（`/patrol/answers`）

> ステータス：ドラフト／要レビュー
> 本番で想定される仕様を記載する。デモ固有の挙動は [README §6](./README.md#6-本仕様と画面デモの差異明記) を参照。

## 1. 概要
- 目的：巡回項目に対する**回答（評価）の選択肢**を登録・編集する。ここで設定した選択肢が巡回実施入力の回答欄に並び、巡回記録の「評価」になる（[02 D-16](./02-巡回パトロール詳細.md)）。
- 利用ロール：**元請のみ**。協力会社（職長）は**サイドバーにメニューを表示せず、URLを直接開いても閲覧できない**（決定事項 D-41）。
- アクセス経路：サイドバー「巡回/パトロール回答編集」。

## 2. 画面要素
- 見出し：「巡回/パトロール回答編集」。
- 選択肢の一覧（枠内・見出し「選択肢」）。1行につき：
  - **選択肢名**（表示のみ）
  - **「追加入力」チェックボックス**
  - **「必須」チェックボックス**
  - **削除ボタン**
- 一覧の下：**選択肢名の入力欄＋「追加」ボタン**。
- **「ヒアリング・所見」の回答設定**（§3.2）。
- 最下部：**「登録」**。

## 3. 表示項目 / 入力項目
| 項目 | 形式 | 内容 |
|---|---|---|
| 選択肢名 | 表示のみ（追加時にテキスト入力） | 例：危険／要是正／普通／良好／模範／該当なし／該当あり |
| 追加入力 | チェックボックス | **その選択肢を選んだときに、コメント（追加入力）欄を表示する** |
| 必須 | チェックボックス | **その追加入力を必須にする**（未入力では巡回記録を登録できない） |

- 選択肢名は**一覧上では編集しない**。文言を変える場合は削除して追加し直す。
- **選択肢名の後からの編集・並び替え・色分け／重み付けは、いずれも提供しない**（決定事項 D-65）。文言を変える場合は削除して追加し直す。

### 3.2 ヒアリング・所見の回答設定（決定事項 D-46）
巡回実施入力の「ヒアリング・所見」を**必須にするかどうか**をここで設定する。

| 設定 | 巡回実施入力での挙動 |
|---|---|
| **必須回答** | 見出しに「（必須）」を付け、未入力では登録できない |
| **任意回答** | 未入力でも登録できる（既定） |

- 設定は現場単位。選択肢の一覧と同じ「登録」でまとめて保存する。
- 確認項目の回答に必須／任意の設定は**設けない**（決定事項 D-66）。確認項目は**全項目回答必須**（[07 §7](./07-巡回実施入力.md)）。

## 4. 機能・操作
| 操作 | 内容 |
|---|---|
| 追加入力の切替 | チェックで追加入力欄の有無を切り替える |
| 必須の切替 | チェックで追加入力の必須／任意を切り替える |
| 削除 | 選択肢を一覧から取り除く |
| 追加 | 入力欄に名称を入れて「追加」。既定は 追加入力=ON・必須=OFF |
| ヒアリング・所見の回答設定 | 必須回答／任意回答を切り替える（§3.2） |
| **登録** | 選択肢と回答設定をまとめて保存する。**登録するまで変更は反映しない** |

### 追加入力と必須の関係（決定事項 D-67）
| 設定 | 巡回実施入力での挙動 |
|---|---|
| 追加入力 **ON** | その選択肢を選ぶと、**自由入力できるメモ欄（テキストボックス）**が表示される |
| 追加入力 **OFF** | 選択肢の回答のみ。メモ欄は表示しない |
| 必須 **ON**（追加入力ON時のみ） | そのメモ欄への入力が**必須**になる |

- 追加入力がOFFのときはメモ欄自体が無いため、**必須は必ずOFF**になる。
- そのため、**追加入力をOFFにすると必須は自動でOFFに切り替わり、必須のチェックボックスは操作不可（disabled）になる**。

## 5. 状態・ロール別表示差
- 元請のみ。協力会社にはメニューを表示せず、閲覧もさせない（D-41）。

## 6. データ・外部連携
- 選択肢マスタは**現場（工事番号）単位**で保持する（想定）。現場ごとに設定できることが前提（[02 D-16](./02-巡回パトロール詳細.md)）。
- **実装に選択肢を固定で持たせない。評価値に依存した分岐を作らない**（D-16）。

- **過去の巡回記録は、実施時点の内容を保持し続ける**（決定事項 D-64）。
  - 巡回記録は**実施時点の評価値（文言）を自分のデータとして持つ**。選択肢を変更・削除しても、過去の記録・帳票・CSVは変わらない。
  - したがって**使用中の選択肢も削除できる**。削除は以後に作成される記録にのみ影響する。
- **選択肢が0件の状態では登録できない**（決定事項 D-68）。0件だと巡回実施入力で回答できなくなるため。

## 7. バリデーション・制約
| 対象 | ルール |
|---|---|
| 選択肢名 | 必須。**同一現場内で重複不可**（重複時は追加させずエラーを表示） |
| 選択肢の件数 | **0件では登録できない**（D-68） |
| 必須 | 追加入力がONの選択肢にのみ設定できる（§4） |
| 権限 | 元請のみ。**API側でも検証すること**（[README §5.2](./README.md)） |

- 選択肢名の文字数上限・選択肢数の上限は**エンジニアマター**（決定事項 D-69）。実装側で決定し本書に反映すること。
- **使用中の選択肢も削除できる**（D-64）。過去の記録は実施時点の値を保持するため、削除時の警告も不要。

## 8. 例外・エッジケース
- 全選択肢を削除して登録した場合。
- 巡回の実施中にマスタが変更された場合。
- 複数の元請ユーザーが同時に編集した場合の上書き（[README §5.3](./README.md)）。

## 決定事項（回答済み）
- **D-46 「ヒアリング・所見」の必須／任意をこの画面で設定できる**（§3.2）。既定は任意回答。
- **D-64 過去の巡回記録は実施時点の評価値を保持し続ける**（§6）。使用中の選択肢も削除でき、過去の記録は変わらない。
- **D-65 選択肢名の後編集・並び替え・色分けは提供しない**（§3）。
- **D-66 確認項目の回答に必須／任意設定は設けない**（§3.2）。全項目回答必須。
- **D-67 追加入力OFFのときは必須を自動でOFFにし、チェックボックスを操作不可にする**（§4）。
- **D-68 選択肢0件では登録できない**（§6・§7）。
- **D-69 選択肢名の文字数・件数の上限はエンジニアマター**（§7）。
