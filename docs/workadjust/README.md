# 作業間調整Pro（/workadjust）詳細仕様 — 枠組み

> ステータス：**ドラフト（デモ実装ベースのたたき台）／要レビュー**
> 目的：本ドキュメント一式を用いて、詳細仕様を engineer に伝え、**要件の認識相違をなくす**。
> 使い方：各画面 md の「⚠️ 未決事項・考慮不足（要確認）」を中心に、○×・補足を記入してください。記載内容はデモ実装から起こした**現時点の想定**であり、確定仕様ではありません。

---

## 0. このドキュメントの読み方

- 各画面ごとに md を用意。共通のテンプレート（下記）に沿って記載しています。
- 記号の意味：
  - **（想定）** … デモ実装から起こした現時点の想定。要確認。
  - **⚠️** … 未決／考慮不足。engineer 実装前に必ず合意が必要な点。
  - `[ ]` … 決定・記入いただきたいチェック項目。

### 画面 md 共通テンプレート

1. 概要（目的・利用ロール・アクセス経路・対応デバイス）
2. 画面要素（レイアウト・主要UI）
3. 表示項目 / 入力項目（列・フォーム・必須/初期値/データソース）
4. 機能・操作（アクション一覧・ロール別可否）
5. 状態・ロール別表示差
6. データ・外部連携
7. バリデーション・制約
8. 例外・エッジケース
9. ⚠️ 未決事項・考慮不足（要確認）

## 4. 横断的な未決事項・考慮不足（**全画面共通で要確認**）

デモは UI 確認用のため、以下は実装前に必ず合意が必要です。

### 4.1 認証・ロール・データスコープ
- [ ] ⚠️ ログイン／認証方式（SSO？ DNN連携？）。デモは「元請／職長」トグルのみ。
- [ ] ⚠️ 職長ユーザーと協力会社の紐付け（DNN連携）の仕様。職長は「自社」のデータのみ見える／編集できる、の範囲定義。
- [ ] ⚠️ 現場（工事番号）のマルチテナント。ユーザーがどの現場に所属し、どの現場を切り替えられるか。

### 4.2 データ永続化・同時実行
- [ ] ⚠️ 保存先（DB/API）とデータ整合。デモはブラウザ内 state で、リロードで消える。
- [ ] ⚠️ 同時編集・排他制御（複数ユーザーが同じ予約枠/作業予定を同時操作）。予約の重複はどう防ぐか（サーバ側チェック必須）。
- [ ] ⚠️ 監査ログ・変更履歴（誰が・いつ・何を 確定/変更/削除したか）。

### 4.3 日付・タイムゾーン
- [ ] ⚠️ 作業日（ヘッダーの日付送り）の基準。端末ローカル日付か、現場基準か。
- [ ] ⚠️ 「今日」の定義（2部制グリッドは端末日付基準で7日間）。日跨ぎ・深夜作業の扱い。
- [ ] ⚠️ ヘッダー日付送りは「予約」「作業予定一覧」でのみ有効（想定）。配置図作成も日付を持つが日付送り対象外にしている点の是非。

### 4.4 外部連携（DNN / NEO / 安全セーフティ）
- [ ] ⚠️ 各連携の方式（API/CSV/画面遷移）・同期タイミング（リアルタイム/バッチ）・マスタの「正」がどちらか。
- [ ] ⚠️ 協力会社・業種・職種マスタ（DNN）、入場人数（DNN）、台紙（NEO）、持込機械（安全セーフティ）の項目マッピング。
- [ ] ⚠️ 連携が無い/失敗した場合のフォールバック表示。

### 4.5 通知・帳票・現場運用
- [ ] ⚠️ 通知は「予約の重複」以外（確定通知・変更通知・予約競合・実績未入力督促等）が必要か。
- [ ] ⚠️ 帳票（作業予定/予約 出力、QR印刷）の用紙・レイアウト・押印運用・保管要件。
- [ ] ⚠️ スマホ/現場のオフライン対応（通信断時の入力・再送）。

### 4.6 バリデーション全般
- [ ] ⚠️ 必須項目・文字数・重複・日付/時間範囲の基準を各画面で統一定義。
- [ ] ⚠️ 削除時の関連データ整合（例：資機材を削除したら、その予約はどうなるか）。

## 5. デモ実装と実仕様の乖離（明記）

- データはすべてブラウザ内のサンプル値。API/DB なし。
- 元請/職長はヘッダーのトグルで切替（本番は認証ベース）。
- 予約の重複防止はクライアント表示のみ（本番はサーバ側チェック必須）。
- 「今日」以外の日付のデータ、過去/未来データの整合はデモ用に簡略化。
- 資機材は高所作業車 4.5m×100・駐車場×100 のサンプルを自動生成。
