# 05. 作業実績入力（QR読み取り後）（/workadjust/actual-input）

> ステータス：ドラフト（デモ実装ベース）／要レビュー

## 1. 概要
- 目的：現場でQRを読み取った協力会社の作業員／職長が、当日の作業実績（作業人数・工数）を入力・送信する。
- 利用ロール：協力会社の作業員／職長。
- アクセス経路：QR読み取り（[04.QR発行]）→ 独立ページ（モバイル想定）。

## 2. 画面要素
- ビュー切替（デモ）：アカウントあり／アカウントなし。
- ヘッダー：工事名／作業実績入力／作業日（＋アカウントあり時は会社名）。
- 本体：
  - **アカウントなし**：会社名を選択 → 実績入力フォーム。
  - **アカウントあり**：会社選択を省略しログイン会社の実績入力へ直行。
- 送信後：完了画面（ブラウザを閉じる案内）。

## 3. 表示項目 / 入力項目
- 会社カード：会社名、入場人数（DNN連携値・想定）。
- 作業行：職種／作業内容、通常作業・早出/残業ごとに 作業人数（予定＝表示）／作業人数（実績＝入力）／工数（入力）。

## 4. 機能・操作
- 会社選択（アカウントなし）／会社選び直し。
- 実績入力→送信→完了。

## 5. 状態・ロール別表示差
- アカウント有無で会社選択の要否が変わる。

## 6. データ・外部連携
- 対象作業の予定：作業予定一覧（当日・当該会社）。
- 入場人数：DNN（出面・日報管理）。
- 送信先：作業予定の実績（[01] の実績と同一データ・想定）。

## 7. バリデーション・制約
- 実績人数・工数は0以上。
- 対象作業日：**当日を既定表示。前日以前も日付選択して記入可（未来日は不可）**（デモ反映済み。QRは日付を持たない＝[04](04-作業実績入力QR発行.md)）。

## 8. 例外・エッジケース
- 対象日に作業予定が無い会社（画面に「作業予定はありません」を表示）。
- 二重送信・再入力：**許可。常に最新で上書き**。

## 決定事項（回答済み）
- **本人特定/認証**：[04](04-作業実績入力QR発行.md) の方針に準拠＝**現場トークン付き恒久URL＋会社選択（アカウントなし）を基本**、監査を強めたい場合は職長のみログイン。※実績入力は資源占有を伴わないため予約QRより低リスク。運用上は**選択した会社名を確認表示**して誤選択を抑止（推奨）。
- **アカウント判定（ログイン会社）**：**ログインユーザーと協力会社設定の職長ユーザーを突合して会社名を識別**（[01](01-作業予定一覧.md) §6 の識別方式と共通）。
- **対象作業日**：当日既定＋前日以前記入可（§7・デモ反映済み）。
- **二重送信・締め**：二重送信可・**常に上書き（last-write-wins）**。締め時刻は設けない（設ける場合は本番で追加）。
- **[01]元請入力との単一ソース化**：同一データを共有し、**元請入力・QR入力のうち後勝ち（常に最新が上書き）**。
- **DNN入場人数との整合チェック**：**不要**（超過警告等は行わない。入場人数は参考表示）。
- **オフライン/通信断**：一時保存は不要。可能なら**通信再開時に自動再送**（ベストエフォート）。
- **現場共用端末のセッション扱い＝A：アカウントなし・ステートレス**を採用。毎回会社選択から開始し、**送信後は入力内容をクリア**（ログイン状態を持たない＝共用端末で前の人の情報が残らない）。ブラウザのオートフィル/キャッシュは最小化。監査が必要な職長のみログイン（送信後/一定時間で自動ログアウト）を上乗せ可。
  - ※ 不採用：B（ログイン必須＝手間・自動ログアウト取りこぼし）／C（個人端末限定＝共用運用ができない）。
