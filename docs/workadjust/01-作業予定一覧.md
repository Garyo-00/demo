# 01. 作業予定一覧（/workadjust）

> ステータス：ドラフト（デモ実装ベース）／要レビュー

## 1. 概要
- 目的：表示中の作業日について、協力会社の作業予定を一覧・作成・確定・実績入力・出力する。
- 利用ロール：元請／職長（下記の差）。
- アクセス経路：サイドバー「作業予定一覧」（ルート）。
- 対応デバイス：PC（テーブル）／スマホ（カード表示）。

## 2. 画面要素
- ツールバー：件数、**協力会社名での検索**、出力、コピー作成（元請ver）、コピー作成（職長ver）、＋新規作成。
- **元請安全指示事項**（その日の全作業に共通）：入力されている場合のみ、**一覧テーブルの上**に表示する。
- 一覧（PC＝テーブル／スマホ＝カード）。**全カラムでソート可能**（ヘッダークリック／初期は業種ソート）。50件ごとにページネーション（表示件数 25/50/100・既定50）。
- 下部：確定／確定解除／実績入力バー（元請のみ）。**各ボタンは対象レコードがある場合だけ表示**し、件数を添える。
  - **確定（N件）**：未確定のレコードがあるとき。
  - **確定解除（N件）／実績入力（N件）**：確定済のレコードがあるとき。
  - **確定済と未確定が混在する日は3つとも並ぶ**（確定済に実績を入力しつつ、追加分を確定できる）。
- モーダル：新規作成・編集／コピー作成／確定（安全指示入力）／実績入力／出力プレビュー。

## 3. 表示項目 / 入力項目
### 一覧の列
- ステータス（未確定／確定済）、協力会社名、業種、職種、作業場所（棟/階/エリア/工区）、作業内容、作業人数（予定）、作業人数（実績）、**安全指示事項**、操作（編集/削除）。
  - **元請安全指示事項は作業予定ごとには表示しない**（日単位のため一覧上部にまとめて表示。§4-2）。
- 並び順：業種を基準（想定）。

### 新規作成／編集フォーム
- 共通：日付（**編集可能**。新規作成時は表示中の日付を初期値／新規・編集とも変更可）、協力会社名（選択＋自由記述。**未登録の協力会社も入力・登録可**）、業種（**選択のみ・自由記述不可**）、職種（業種に紐づく・**選択のみ**）、職長（**協力会社の職長ユーザーから選択**。選択肢は自動反映され、既定は表示順の先頭。職長が複数いる会社は切替可）。
- 作業ブロック（複数追加可）：**棟・階・工区・エリア**（自由記述＋履歴）、作業内容（自由記述＋履歴）、作業人数・工数（通常作業／早出・残業作業でそれぞれ人数・工数）。**履歴のスコープは §6 参照**。
  - **入力順は 棟 → 階 → 工区 → エリア**（工区のほうが上位の区分のため。作成・編集フォームでの並び順）。
  - **作業内容は必須**。作業ブロックが複数ある場合は、未入力のブロック番号を示して知らせる。
  - **安全指示事項**（任意・255文字まで）：**職長が記入する想定**だが、**職長の入力漏れに備えて元請も予定作成時に入力できる**。協力会社単位の履歴をサジェスト表示する。出力の「安全指示事項」列に出る。
  - **工数は作業人数から自動入力**：**通常作業**の作業人数を変えると、工数に**人数 × 8h**を自動でセットする（手入力での上書きも可）。**早出・残業作業は自動計算しない**（1人あたり8時間にならないため）。画面上に注記は出さない。

#### ⚠️ 工事種別による項目の出し分け（本番で要実装）
**プロジェクトの工事種別が「土木」の場合、作業場所の「棟」「階」を非表示にする**（土木工事では建物の棟・階という区分を持たないため）。

- 対象は**作成・編集フォームの入力欄**と、**一覧・帳票の作業場所の表示**。非表示時は工区・エリアのみで作業場所を構成する。
- 判定に使うのは**プロジェクト（現場）の工事種別**であり、作業予定1件ごとの属性ではない。
- ⚠️ **工事種別の保持場所・値の定義は未確定**（DNN側のプロジェクト情報か、本アプリのプロジェクト設定か）。少なくとも「土木」とそれ以外を判別できる必要がある。
- ※ **デモ未実装**：本デモには工事種別を設定する画面が無いため、常に棟・階を表示している。
- **1回の作成で作業ブロック分のレコードを生成**（編集は1レコード＝1ブロック）。
- **使用する資機材・ゲート**（作業ブロックごと・任意）：[07-資機材ゲート登録](07-資機材ゲート登録.md) で**予約表示ONの資源**から**複数選択**（プルダウン＋チェックボックス）。詳細は §4-4。

### 一覧での表示
- 作業内容の下に、使用する資機材・ゲートを**チップで表示**。**予約と紐づいていれば青、紐づいていなければ橙**。時間帯はツールチップで確認する。

## 4. 機能・操作
- 新規作成：ブロック複数→複数レコード生成（status=未確定）。
- 編集／削除：**確定済は不可**（確定解除が必要）。
- コピー作成（元請）：協力会社別に**各社ごとの直近5件**を表示→選択して表示中の日付に一括登録。**安全指示事項は引き継がず、その他の項目は完全に引き継ぐ**。
- コピー作成（職長）：**自身が作成した予定の直近5件**（会社をまたがず通算5件）を表示→選択して表示中の日付に複製（引き継ぎルールは元請版と同じ）。
- **コピー候補の「直近5件」の定義**：表示中の日付より前の予定を対象に、**日付の新しい順**（同日内は登録の新しい順）で5件。**日数ではなく件数**で数える（旧仕様の「元請＝直近3日／職長＝直近5日」から変更）。
- 確定（元請）：未確定を一括確定。**確定時に元請安全指示事項を入力（必須・255文字まで）**。**レコード単位の確定は行わない（当日の未確定を一括確定）**。詳細は §4-2。
- 確定解除（元請）：確定済を未確定に戻す（編集可能化）。
- 実績入力：確定済に対し作業人数（実績）・工数を入力（会社ごとにまとめ、入場人数はDNN連携時のみ表示）。**元請は一括入力、職長は各レコードの「実績入力」ボタンから入力**（確定後）。**予定と実績の突合・不一致アラートは行わない**。

- 出力（元請）：**確定済のみ**A4帳票（業種・職種列を含む／職長名なし）。**押印はシステム化せずアナログ運用（押印欄は空欄で出力）**。
  - 表には**「安全指示事項」列**（作業予定ごと）を出す。**元請安全指示事項は表には入れず、各ページのフッターに出す**（§4-2）。
  - **帳票ヘッダーの左上に工事番号は出力しない**（工事名称のみ）。予約・配置図作成の出力も同じ扱い（[02](02-予約.md)／[03](03-配置図作成.md)）。

### 4-2. 安全指示事項（作業予定ごと）と元請安全指示事項（1日単位）
**2種類の安全指示を別々に持つ。**

| | 安全指示事項 | 元請安全指示事項 |
|---|---|---|
| 単位 | **作業予定レコードごと** | **作業日ごとに1つ**（その日の全作業に共通） |
| 入力する人 | **職長**（想定）。入力漏れに備え**元請も入力可** | **元請** |
| 入力する場面 | **作成・編集フォーム**（任意・255文字まで） | **確定ダイアログ**（必須・255文字まで） |
| 一覧での表示 | **「安全指示事項」列** | **テーブルの上**（入力済みのときのみ） |
| 出力での表示 | 表の**「安全指示事項」列** | **各ページのフッター** |

- **作業予定ごとの元請安全指示事項は廃止**した（従来は確定時に作業ごとに入力していた）。一覧・帳票とも、作業予定の行に元請安全指示事項は出さない。
- **元請安全指示事項は複数ページでも全ページのフッターに出す**（ページをまたいで参照できるようにするため）。
- **再確定時の扱い**：確定後に未確定の予定が追加され、あらためて確定する場合は、**すでに入力済みの元請安全指示事項を入力欄の初期値として表示**し、そのまま確定するか、更新して確定できる。
- 入力補助：安全指示事項は**協力会社単位の履歴**、元請安全指示事項は**他の日に入力した内容**をサジェスト表示する（いずれも重複排除・最新5件）。

### 4-3. 実績入力者の記録
**誰が実績を入力したかを作業予定レコードごとに保持する。**

- 保持する項目は**作成ユーザー**（最初に実績を入力した人）と**最終更新ユーザー**（最後に更新した人）の2つ。
- **値が変わった行だけ記録する**。一括保存で触っていない行まで更新者が書き換わらないようにする。
  - 初回入力：作成ユーザーに記録（最終更新ユーザーは空）。
  - 2回目以降：最終更新ユーザーを都度上書き（作成ユーザーは変えない）。
- **記録する名前の取得元**：
  - 元請・職長（ログインあり）＝**ログイン中のユーザー**。
  - QRからの入力＝**送信フォームの「入力者（お名前）」欄の値**（アカウントありはログインユーザーで固定、アカウントなしは記入。[05-作業実績入力](05-作業実績入力.md)）。
- **帳票への出力**：作業予定一覧の出力に**「実績入力者」列**を設け、**作成ユーザーと最終更新ユーザーを並べて表示**する。
  - 同一人物が入力・更新した場合は**1名**、別人が更新した場合は**2名**、実績未入力なら**0名（空欄）**。
- ※ デモは認証が無いため、ログインユーザーはロールから決め打ち（元請＝元請ユーザーの先頭／職長＝自社の職長ユーザーの先頭）。本番は認証セッションのユーザーを使う。

### 4-4. 資機材・ゲート予約との紐づけ
作業予定に「使用する資機材・ゲート」を持たせ、[02-予約](02-予約.md) の予約と結びつける。

- **紐づけの単位**：作業ブロック（＝1レコード）ごと。1つの予定で複数の資機材・ゲートを選べる。
- **紐づけは予約IDで保持する（確定事項）**：いったん紐づいた予約は**予約IDで固定的に保持**する。
  - **予定の日付を変更しても紐づけは外れない**。予約の日付と作業日がずれた場合は「（予約日 YYYY-MM-DD）」を添えて**橙色で警告表示**し、ずれていることが分かるようにする（紐づけ自体は維持）。
  - 予約IDを持たない場合のみ、**同じ作業日・同じ資源・同じ協力会社**の予約を探して紐づける。照合で見つかった予約IDは**保存時に確定して書き込む**ため、以後は日付を変えても保持される。
  - 協力会社名が未入力のうちは照合しない（予約は会社単位で持つため）。「協力会社名を入力すると予約を照合します」と表示。
- **1つの予約に紐づけられる作業予定は1件まで（確定事項）**：逆に、**1つの作業予定には複数の資機材・ゲート（＝複数の予約）を紐づけられる**。
  - すでに他の作業予定が掴んでいる予約は、照合の対象から外す。
  - その資源に自社の予約はあるが他の予定に取られている場合は「HH:MM〜HH:MM の予約は「〇〇／△△」に紐づけ済み」と表示し、**「＋ 別の予約を作成」**で自分用の予約を作れる。
  - コピー作成の一括登録でも同様。複製する予定どうしで同じ予約を奪い合わないよう、1件ずつ順に割り当てる。
- **予約が無い場合**：その場で**予約を作成**できる。開始／終了（＋ゲートは車種）を指定すると、通常予約として登録し、同時に紐づける。
  - 作成される予約の**協力会社名・日付は作業予定から引き継ぐ**。**作業内容は作業ブロックの作業内容**、**作業場所は棟・階・エリア・工区**を引き継ぐ（ゲートは作業場所なし＝[02](02-予約.md) §3）。
  - 時刻の候補・刻みは**資源種別ごとの「予約時間設定」「予約時間間隔設定」に従う**。初期値は 08:00〜10:00。
- **他社の予約しか無い場合**：「自社の予約なし（他社の予約あり）」と表示し、自社の予約を作成できる（重複はブロックせず、[02](02-予約.md) の重複警告に委ねる）。
- **資機材を選んだだけで予約を作らない**ことも許容する（後から予定の編集画面で作成できる）。
- **紐づけを解除しても予約は残す（確定事項）**：予定から資機材を外しても、そこから作成した予約は削除しない（予約側で明示的に削除する運用）。

### 4-5. コピー作成の手順（3手順）
コピー作成は**手順1：複製元の選択 → 手順2：紐づける資機材・ゲートの選択 → 手順3：資機材・ゲートの予約**の3画面構成とする。

#### 手順1：複製元の選択
- 協力会社別に直近5件を表示（§4）。各行には、その予定が使う**資機材・ゲートをチップで表示**する（色は一覧と同じ。青＝予約と紐づけ済み／橙＝紐づいていない）。
- ボタン：`次へ：資機材・ゲートの選択（N 件）`

#### 手順2：紐づける資機材・ゲートの選択
- **複製する予定を1行ずつ並べ、予定ごとに使用する資機材・ゲートを選ぶ**（複数選択）。
- **初期値は複製元の選択内容**。
- **資機材を使っていない複製元も必ず一覧に出す**（コピーのタイミングで新たに紐づけられるようにするため）。使わない場合は空のままでよい。
- ボタン：資機材を1件以上選んでいれば `次へ：資機材・ゲートの予約（N 件）`、1件も選んでいなければ `YYYY年M月D日（曜日）の予定として登録（N 件）`（手順3を挟まず登録）。

#### 手順3：資機材・ゲートの予約
手順2で紐づけた**予定 × 資機材**の組ごとに、予約を作成する。

- **予約日は複製先の作業日で固定**（作業予定と同じ日）。
- **開始・終了は複製元の予約を引き継ぐ**。複製元に予約が無い場合は**空欄**で始める。
- **予約を作成しないこともできる**：行ごとの「予約を作成する」チェックで切り替える。**既定は複製元に予約があった行のみON**。「予約をまとめて作成する」で一括切替も可能。
- **入力できる項目**：
  - **協力会社名**（初期値＝作業予定の協力会社名）
  - **作業内容**（初期値＝複製元の作業内容。25文字まで）
  - 開始・終了
  - **車種**（**ゲートのみ**）
- **複製先の日付にすでに空いている自社の予約がある場合は、作成せずその予約に紐づける**（重複作成を避けるため）。その行は入力欄を出さず「予約あり HH:MM〜HH:MM に紐づけ」と表示する。1予約＝1予定の原則（§4-4）に従い、他の予定が掴んでいる予約は対象外。
- **入力チェック**：作成をONにした行は、協力会社名・作業内容・開始・終了（終了は開始より後）が必要。ゲートは車種も必須。
- ボタン：`YYYY年M月D日（曜日）の予定として登録（N 件／予約M 件を作成）`

## 5. 状態・ロール別表示差
- ステータス：未確定→確定済。確定済の行は薄グレー、編集/削除ボタンは無効。
- 職長：作成・編集、および**確定後の各レコードの実績入力**が可能。確定／確定解除／出力は不可。
- **データスコープ（職長）：他社分も閲覧可能。編集・削除は「自身が作成したレコード」または「職長欄が自分であるレコード」のいずれかに該当するもののみ**（自社ではなくユーザーで識別）。元請が作成したレコードでも、職長欄に自分が設定されていれば編集・削除できる。元請が協力会社設定を行っていない状態を想定し、**作成は自社に限定せず自由入力を容認**。
- 運用フロー：職長が作成 → 元請が確定（安全指示入力）→ 元請または職長が実績入力。**実績を入力・更新したユーザーはレコードに記録され、帳票に出力される**（§4-3）。
- 「作業人数（予定）」の一覧表示は**通常作業のみ**を集計（早出・残業は含めない）。
- 削除・確定解除の操作履歴（監査）は**ユーザー画面には表示しない**（dev側でログ保持）。**確定後の変更通知も行わない**。

## 6. データ・外部連携
- 協力会社／業種／職種／職長：DNN（協力会社設定）由来。
- 入場人数（実績入力時）：DNN（出面・日報管理）連携。連携が無ければ表示しない（連携の有無はfunctionフラグで確認）。

### 入力履歴（サジェスト）のスコープ
対象項目：棟・階・エリア・工区、作業内容（いずれも自由記述＋履歴）。
**履歴は「入力ユーザーごと（個人単位）」で保持・表示する**（＝各ユーザーが自分の入力履歴のみを利用。協力会社単位・現場単位での共有はしない）。
> 変更理由：当初は「同一協力会社に所属するユーザー間で共通」としていたが、ユーザー×所属会社の管理が現実的でないため、**ユーザー個人単位**に変更（協力会社ごとの共通は廃止）。

- 元請ユーザー・協力会社ユーザーいずれも**個人単位**（会社/現場での共有なし）。
- **未登録の協力会社**でも予定の登録は可能。表記ゆれは許容し、後からのマージは想定しない。
- **履歴の保持ルール**：保存期間の指定なし／**件数は5件まで**／**重複は排除**／並び順は**最新の作成データを参照**／項目（棟・階・エリア・工区・作業内容）で共通の扱い。
- ※ 別途、**安全指示事項（作業予定ごと）の履歴は協力会社単位**、**元請安全指示事項（日単位）の履歴は他の日の入力内容**（いずれも5件・実装済み。§4-2）＝上記の入力履歴とはスコープが異なる。
- ※ デモは入力履歴（`WA_HISTORY`）を全体共通で保持しており、個人単位のスコープ分けは未実装（本番仕様として要実装）。
