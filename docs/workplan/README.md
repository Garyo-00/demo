# 作業計画書NEO（/workplan-neo）詳細仕様 — 枠組み

> ステータス：**ドラフト（デモ実装ベースのたたき台）／要レビュー**
> 作成日：2026/08/06
> 目的：本ドキュメント一式を用いて、詳細仕様を engineer に伝え、**要件の認識相違をなくす**。
> 使い方：各 md の「⚠️ 未決事項・考慮不足（要確認）」を中心に、○×・補足を記入してください。記載内容はデモ実装から起こした**現時点の想定**であり、確定仕様ではありません。

---

## 0. このドキュメントの読み方

- 記号の意味：
  - **（想定）** … デモ実装から起こした現時点の想定。要確認。
  - **⚠️** … 未決／考慮不足。実装前に必ず合意が必要な点。
  - `[ ]` … 決定・記入いただきたいチェック項目。
- 画面 md は共通テンプレート（1.概要／2.画面要素／3.表示・入力項目／4.機能・操作／5.状態・ロール別表示差／6.データ・外部連携／7.バリデーション・制約／8.例外・エッジケース／9.⚠️未決事項）に沿う。

## 2. 業務手順（全体フロー）

```
[1] テンプレートを設定する（元請＝ゼネコン）
      作業計画書の書式はゼネコン各社で異なるため、項目を自由に編集できる
        ↓  テンプレートを選択して作成
[2] 作業計画書を新規作成する（職長＝協力会社）
      ・どの作業に対する計画書かをテンプレートから選択 → 選んだテンプレートで入力項目が変わる
      ・使用する承認フローを選択（複数設定されたフローから選ぶ）
      ・別サービス（AS＝持込機械の登録・点検サービス）に登録された機械に紐づけできる
      ・承認前でも一覧には並ぶ
        ↓  承認依頼
[3] 承認・否認・編集（原則、元請）
      ・承認者は「承認フロー設定」で設定されたユーザー
      ・承認時に安全指示事項を入力できる（[02] 参照）
        ↓  承認済のみ公開
[4] 現場での閲覧・チェックリスト実施（作業員）
      ・機械個体に貼られた点検QRを読むと、その機械に紐づく「当日」の承認済作業計画書が表示される
      ・当日に複数紐づく場合は選択して閲覧
      ・閲覧だけでなく、テンプレートで設定したチェックリスト（運転者としての注意事項・確認事項）を実施
```

## 5. これまでに確定した内容（指示ベース）

1. **ルート（`/`）のデモ画面一覧に「作業計画書NEO」を追加**。現時点で実装するのは**テンプレート設定のみ**、他メニュー（作業計画書一覧／作業配置図設定／承認フロー設定／マニュアル）は**空ページ**（後日実装）。
2. **テンプレート設定の構成**（[01](./01-作業計画書テンプレート設定.md)）
   - テンプレート名／必須項目（固定）／**ブロック**／書類添付／チェックリスト。
   - 作業計画書は**ブロック単位**で構成する。従来の「共通項目」「作業内容」は廃止し、行き先未定の項目は**その他ブロック（仮）**にまとめている。
3. **ブロック構成**：基本情報（作業配置図＋作業期間）／機械／積荷／人員配置／クレーン／調査／厳守事項・周知事項／その他（仮）。中身の仕様が決まっている**基本情報・クレーン・その他**はブロック内に設定UIを持ち、それ以外は使用ON/OFFのみ。
4. **チェックリストはタブ構成**で、1テンプレートに**複数**持てる。各リストに「チェックリスト名」「実施者の役割」、行は **内容／必須／備考**（回答形式は持たない）。
5. **テンプレート一覧**は「テンプレート名／種別（マスタ）／⋮メニュー」＋ページネーション。`【テンプレート用】〜` は**マスタ**として区別。
6. **安全指示事項**（[02](./02-安全指示事項.md)）
   - **承認時に元請が安全指示事項を入力**できる（ブロックのON/OFFは廃止し、常に入力可とした）。
   - 1つの作業計画書に対し**複数**作成でき、**作業内容ごと**に作る（「作業内容＋安全指示事項」のかたまりを承認者が任意の数だけ追加）。
   - 承認ユーザーが複数いる場合、**他ユーザーが登録した内容を上書きできる**。
   - 同時編集の衝突回避方法は**推奨方式を採用**（[02 §7](./02-安全指示事項.md) 参照）。

## 6. 横断的な未決事項（**全画面共通で要確認**）

### 6.2 データ永続化・同時実行
- [ ] ⚠️ 保存先（DB/API）。デモはブラウザ内 state のためリロードで消える。

- [ ] ⚠️ 変更履歴・監査ログ（誰が・いつ・何を 作成/承認/上書きしたか）。

### 6.3 テンプレートと作成済み作業計画書の関係
- [ ] ⚠️ テンプレートを**後から変更**したとき、作成済み・承認済みの作業計画書に影響するか（**スナップショット方式を推奨**：作成時点のテンプレート内容を計画書に写し取り、以後テンプレート変更の影響を受けない）。
- [ ] ⚠️ テンプレート削除時、それを使った既存の作業計画書の扱い。
- [ ] ⚠️ マスタテンプレートの編集・削除可否（デモでは**不可**、複製して使う想定）。

### 6.4 AS（安全セーフティ）連携

## 7. デモ実装と実仕様の乖離（明記）

- データはすべてブラウザ内のサンプル値。API/DB なし（リロードで初期化）。
- 元請／職長はヘッダーのトグルで切替（本番は認証ベース）。
- ブロックのうち機械・積荷・人員配置・調査・厳守事項/周知事項は**使用ON/OFFのみ**で、中身は未実装のプレースホルダ。
- 設定画面（[03](./03-設定.md)）のトグルは値を保持するだけで、元請確認の画面は未実装（打合せ参加者サインのみ [04](./04-打合せ参加者サイン.md) で実装済）。
- 添付ファイルはファイル名の保持のみ（アップロードしない）。
